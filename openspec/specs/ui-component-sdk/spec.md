# ui-component-sdk Specification

## Purpose
为前端提供框架无关的抽象组件运行时：按组件 type 注册处理器，把 JSON 组件树交给处理器渲染，并在单个节点出错时隔离故障、按可覆盖的降级策略继续运行。

## Requirements

### Requirement: 处理器按类型与命名空间注册

系统 SHALL 允许为组件 type 注册处理器，并按「命名空间 + type」两级查找；同一命名空间内重复注册同一 type 时，除非显式声明覆盖，否则 SHALL 拒绝本次注册并告警。

#### Scenario: 首次注册成功

- **WHEN** 调用方在某命名空间下为尚未注册的 type 注册处理器
- **THEN** 注册成功，按该 type 可查询到刚注册的处理器

#### Scenario: 重复注册被拒绝

- **WHEN** 同一命名空间内已存在某 type 的处理器，调用方未声明覆盖再次注册
- **THEN** 注册被拒绝，原处理器保持不变，并产生一条告警

#### Scenario: 显式覆盖生效

- **WHEN** 调用方声明覆盖后为同一命名空间的同一 type 重新注册
- **THEN** 新处理器替换旧处理器，后续按该 type 查询返回新处理器

#### Scenario: 命名空间回退查询

- **WHEN** 当前命名空间下某 type 未注册处理器，而默认命名空间下已注册
- **THEN** 按该 type 查询时回退返回默认命名空间的处理器

### Requirement: 运行组件树并自动注入运行时对象

系统 SHALL 在运行入口接收整棵组件树与消息对象，按根节点的 type 查找并执行对应处理器，并向处理器自动注入整棵树、当前节点、消息对象与 SDK 实例自身。

#### Scenario: 命中处理器

- **WHEN** 根节点的 type 在注册表中命中处理器
- **THEN** 该处理器被执行，且能拿到整棵树、当前节点、消息对象与 SDK 实例

#### Scenario: 处理器无返回值

- **WHEN** 处理器执行完毕
- **THEN** 调用方不从运行入口获得渲染结果，渲染效果由处理器自行产生

#### Scenario: 未初始化即运行

- **WHEN** 实例尚未初始化就被要求运行组件树
- **THEN** 系统按未初始化的既定策略处理并告警，不抛出未捕获异常中断调用方

### Requirement: 创建预绑定的节点处理器

系统 SHALL 提供一种创建方式，在给定整棵树与消息对象后返回一个处理器，调用该处理器时只需传入当前节点即可执行，无需重复传入树与消息对象。

#### Scenario: 预绑定后执行

- **WHEN** 用整棵树与消息对象创建处理器，再传入某个节点执行
- **THEN** 执行时该节点对应的逻辑被调用，且树与消息对象为创建时绑定的那份

#### Scenario: 创建阶段触发钩子

- **WHEN** 预绑定处理器创建完成
- **THEN** 系统触发对应的组件创建钩子与事件，钩子能拿到该处理器

### Requirement: 子节点派发由处理器驱动

系统 SHALL NOT 在运行时自动遍历并渲染整棵树；处理器 SHALL 通过预绑定处理器主动派发其子节点，并可自行决定跳过其中某些子节点。

#### Scenario: 处理器选择性派发

- **WHEN** 处理器只对 `children` 中的一部分子节点执行派发
- **THEN** 被跳过的子节点不被处理，其余照常处理，系统不因此报错

#### Scenario: 不派发子节点

- **WHEN** 处理器执行时不派发任何子节点
- **THEN** 该节点的子树不被处理，运行流程照常继续

#### Scenario: 派发时的错误隔离

- **WHEN** 派发的某个子节点处理器抛出异常
- **THEN** 该子节点被降级处理，同一处理器后续要派发的子节点照常执行

### Requirement: 生命周期阶段与钩子

系统 SHALL 维护「创建 → 初始化 → 运行 → 销毁」的实例生命周期，每个阶段触发对应事件，并允许调用方通过钩子介入各阶段。

#### Scenario: 阶段顺序

- **WHEN** 依次调用创建、初始化、运行
- **THEN** 事件按创建、初始化、运行的顺序依次触发，不出现乱序

#### Scenario: 钩子收到错误

- **WHEN** 某阶段的处理器执行抛出异常
- **THEN** 错误钩子被调用并收到封装后的错误，生命周期不被中断

#### Scenario: 销毁幂等

- **WHEN** 实例已销毁后再次调用销毁
- **THEN** 第二次调用不产生副作用，也不抛出异常

### Requirement: 销毁时清理注册表与订阅

系统 SHALL 在销毁时注销全部处理器并移除全部消息订阅，销毁后按已注销类型运行将走未注册降级路径。

#### Scenario: 销毁后查询处理器

- **WHEN** 实例销毁后按某 type 查询处理器
- **THEN** 查询不到该处理器，注册表为空

#### Scenario: 销毁后收到消息

- **WHEN** 实例销毁后有消息发出
- **THEN** 已移除的订阅不再被回调

### Requirement: 消息通知机制

系统 SHALL 提供消息的注册、注销与发出机制；消息内容的语义由使用方自行约定，SDK 只承载传递。

#### Scenario: 注册后收到通知

- **WHEN** 为某事件注册回调后发出该事件
- **THEN** 该回调被调用，并收到发出时携带的数据

#### Scenario: 注销后不再收到

- **WHEN** 某事件的回调被注销后再发出该事件
- **THEN** 该回调不再被调用，其它仍注册的回调不受影响

#### Scenario: 同事件多回调

- **WHEN** 同一事件注册了多个回调并发出该事件
- **THEN** 所有已注册的回调均被调用

### Requirement: 单节点渲染错误隔离

系统 SHALL 捕获处理器执行中抛出的异常并封装为带节点标识、type 与阶段的错误对象，交由错误处理器处理，且该节点的失败 SHALL NOT 中断其余节点的执行。

#### Scenario: 处理器抛出异常

- **WHEN** 某节点的处理器执行时抛出异常
- **THEN** 异常被捕获并封装为含节点标识、type 与阶段的错误，交由错误处理器处理

#### Scenario: 同级后续节点继续执行

- **WHEN** 某个节点执行失败且其后还有同级节点
- **THEN** 后续同级节点照常执行，整棵树不因单点失败而中断

#### Scenario: 错误钩子被调用

- **WHEN** 渲染过程中产生封装后的错误
- **THEN** 错误钩子被调用，调用方能观察到该错误

### Requirement: 未注册类型降级

系统 SHALL 在节点 type 未注册处理器时走降级路径交由错误处理器决定结果，且 SHALL 保留该节点的子节点，不出现整块内容丢失。

#### Scenario: 未注册类型渲染降级

- **WHEN** 组件树中出现注册表内不存在的 type
- **THEN** 该节点按错误处理器给出的降级形态处理，不抛出未捕获异常

#### Scenario: 子节点保留

- **WHEN** 被降级的节点仍有子节点
- **THEN** 子节点仍被继续处理，不因父节点未注册而整块丢弃

### Requirement: 错误处理器可被覆盖

系统 SHALL 默认注册一个全局错误处理器，负责输出错误并给出降级形态；调用方 SHALL 可用覆盖方式替换为自己的错误处理实现。

#### Scenario: 使用默认错误处理器

- **WHEN** 未注册自定义错误处理器而发生渲染错误
- **THEN** 默认错误处理器被调用，错误被输出且节点降级为占位形态

#### Scenario: 覆盖为自定义实现

- **WHEN** 调用方以覆盖方式注册了自己的错误处理器后发生渲染错误
- **THEN** 自定义错误处理器被调用，降级形态由其决定

### Requirement: 保持框架无关

SDK SHALL NOT 直接操作 DOM、绑定具体 UI 框架，也不 SHALL 提供组件通信总线协议；渲染效果完全由注册的处理器自行实现。

#### Scenario: 不依赖 DOM 运行

- **WHEN** 在没有 DOM 环境的条件下完成注册与运行
- **THEN** 注册、运行与生命周期流程照常完成，不因缺少 DOM 而失败

#### Scenario: 处理器自由渲染

- **WHEN** 不同实现为同一 type 注册了不同处理器
- **THEN** 两者均能完成运行，SDK 不对渲染产物形态作任何约束
