# Spec Delta

## Purpose

用 JSON 描述抽象组件的功能骨架，让业务模块以统一声明的方式交付后台页面，由后端在启动期装配成内存注册表并以接口对外提供，前端按组件类型自主渲染，从而实现布局与样式的分离。描述只表达语义，不限定前端的视觉呈现方式。

## ADDED Requirements

### Requirement: 抽象组件描述的通用结构
系统 SHALL 接受形如组件树的抽象组件描述：每个节点至少携带 `type`，可携带 `id`、`name`、`order`、`router`、`description`、`api`、`layout`，以及该类型定义声明的专有属性；子组件通过 `containers` 声明。全部类型名与属性名均为 snake_case。

#### Scenario: 节点以 type 标识类型
- **WHEN** 一条描述节点缺少 `type`
- **THEN** 该节点被判定为不合法，不进入组件注册表

#### Scenario: 子组件通过 containers 声明
- **WHEN** 某节点的 `containers` 中声明了子节点
- **THEN** 子节点作为该节点的子组件一并进入组件注册表

#### Scenario: 同级顺序由 order 决定
- **WHEN** 同一父节点下的兄弟节点声明了不同的 `order`
- **THEN** 组件注册表中的同级顺序与 `order` 升序一致

#### Scenario: 布局节点声明方位
- **WHEN** 一个 `layout` 节点声明了 `layout` 方位
- **THEN** 该节点按声明的方位进入应用外壳树，未声明方位的按 `center` 处理

### Requirement: 装配描述由业务模块按约定路径提供
系统 SHALL 从业务模块随构件发布的抽象组件装配描述加载页面装配，装配描述以 JSON 形式位于约定的 `ui/<page>/compose.json` 路径，每个文件声明一棵组件树。

#### Scenario: 业务模块声明页面
- **WHEN** 业务模块在 `ui/user-center/compose.json` 声明一棵组件树
- **THEN** 系统启动后该组件树的全部节点可从组件描述接口获取

#### Scenario: 业务模块未声明页面
- **WHEN** 某业务模块未提供任何装配描述
- **THEN** 系统正常启动，组件注册表中不包含该模块的任何节点

#### Scenario: 装配描述不是合法 JSON
- **WHEN** 某个装配描述无法解析
- **THEN** 该文件被跳过并记录告警，其余装配描述正常装配且系统正常启动

### Requirement: 装配描述按顶层类型归宿
系统 SHALL 在启动装配时按 `compose.json` 顶层节点的类型决定归宿：顶层为 `application` 的作为应用树，顶层为导航容器的按 `order` 合并进应用树的对应方位，其余类型作为页面片段按顶层节点的 `router` 挂载到应用树中 `router` 相同的菜单节点下。

#### Scenario: 导航片段合并进应用外壳
- **WHEN** 某装配描述的顶层节点是 `nav_group`
- **THEN** 该分组按 `order` 合并进应用外壳树的左侧导航菜单列表

#### Scenario: 页面片段按 router 挂载
- **WHEN** 某装配描述的顶层节点是 `dataset` 且 `router` 为 `system/user`
- **THEN** 该数据表挂载到应用外壳树中 `router` 为 `system/user` 的菜单节点之下

#### Scenario: 页面片段没有挂载目标
- **WHEN** 页面片段的 `router` 在应用外壳树中没有对应菜单节点
- **THEN** 该片段原样进入组件描述接口的 `pages`，不产生加载错误

### Requirement: 构建期聚合索引与运行时固定路径读取
系统 SHALL 在构建期把各模块的装配描述与组件类型定义聚合为单一索引产物并落于 `META-INF/ping/` 下的固定路径，运行时只读取该固定路径；classpath 中其它位置的描述文件不参与运行时加载。

#### Scenario: 索引之外的描述不生效
- **WHEN** 某模块把组件描述放在约定位置之外的 classpath 路径下
- **THEN** 该描述不进入组件注册表，且不产生加载错误或启动失败

#### Scenario: 打包产物缺少聚合索引
- **WHEN** 打包产物中不存在聚合索引文件
- **THEN** 系统正常启动，组件注册表为空，组件描述接口返回空集合

#### Scenario: 同名描述的位置收敛
- **WHEN** 多个 jar 中存在同路径的描述文件
- **THEN** 只有被聚合进索引的那一份生效，运行时不因路径重复而报错

### Requirement: 启动后一次性装配进内存注册表
系统 SHALL 在应用启动后一次性把组件描述装配进内存注册表，后续请求只读内存，不重复读取描述文件。

#### Scenario: 重复请求结果一致
- **WHEN** 客户端连续多次请求组件描述接口
- **THEN** 每次响应内容一致

#### Scenario: 启动后修改描述不生效
- **WHEN** 组件描述文件在应用启动完成后被修改
- **THEN** 组件注册表保持不变，需重启应用才能反映修改

### Requirement: 仅被标注的接口可被装配描述引用
系统 SHALL 只把被接口引用注解标注的请求处理方法识别为可被装配描述引用的组件 API，未标注的方法不参与引用解析。

#### Scenario: 标注过的接口可被引用
- **WHEN** 某接口方法带接口引用标注且装配描述引用了它
- **THEN** 该引用可被解析

#### Scenario: 未标注的接口不可被引用
- **WHEN** 装配描述引用了一个带同名标识但未标注的接口方法
- **THEN** 该引用不被解析，组件的接口引用保持原样并记录告警

### Requirement: 接口引用被解析为完整接口描述
系统 SHALL 在启动装配时把装配描述中的接口引用标记解析为完整接口描述，描述至少包含请求方法、请求路径、入参结构与出参结构，解析依据为打包期生成的 OpenAPI 文档。

#### Scenario: 引用被替换为完整描述
- **WHEN** 装配描述引用 `@ResourceReference:获取用户列表` 且对应接口已标注
- **THEN** 组件的 `api` 字段被替换为含方法、路径、入参结构、出参结构的完整描述

#### Scenario: 引用目标不存在
- **WHEN** 装配描述引用了一个在 OpenAPI 文档中不存在的标识
- **THEN** 该组件的接口引用保持原样，系统记录告警且启动不失败

#### Scenario: 打包期文档缺失
- **WHEN** 打包产物中不存在 OpenAPI 文档
- **THEN** 全部接口引用保持原样，组件装配的其余部分正常完成且系统正常启动

### Requirement: 接口出入参成为组件的数据契约
系统 SHALL 把被引用接口的请求参数结构作为该组件的输入参数定义，把响应结构作为该组件的渲染数据契约，二者随组件一并交付给前端。

#### Scenario: 查询接口的入参成为输入参数
- **WHEN** 某数据组件引用了带查询条件的接口
- **THEN** 该组件携带与查询条件对应的输入参数定义

#### Scenario: 无入参接口
- **WHEN** 被引用接口没有请求参数
- **THEN** 该组件的输入参数定义为空

#### Scenario: 响应结构成为渲染契约
- **WHEN** 被引用接口的响应为对象数组
- **THEN** 该组件的渲染数据契约反映该响应结构

### Requirement: 内置常用后台管理抽象组件类型
系统 SHALL 内置 16 种常用后台管理抽象组件类型：`application`、`layout`、`menu`、`nav_group`、`tabs`、`breadcrumb`、`dataset`、`query`、`column`、`row_action`、`form`、`field`、`form_action`、`action`、`placeholder`、`empty`。

#### Scenario: 类型定义可被获取
- **WHEN** 前端请求组件描述接口
- **THEN** 返回内容包含上述全部 16 种类型的定义

#### Scenario: 类型定义可扩展
- **WHEN** 模块在约定位置提供了新的组件类型定义
- **THEN** 新类型与内置类型一并进入组件注册表

### Requirement: 数据类组件按逻辑数据表建模
系统 SHALL 把 `dataset` 描述为逻辑数据表，其输入参数由 `query` 描述、展示列由 `column` 描述、行列级功能由 `row_action` 与列声明的功能描述承载；该描述 SHALL 只约束语义，不限制前端的渲染形态。

#### Scenario: 表格与其输入参数分离声明
- **WHEN** 某 `dataset` 节点带有独立的 `query` 子节点
- **THEN** `query` 中的参数作为该数据表的输入参数交付给前端

#### Scenario: 展示列声明排序能力
- **WHEN** 某 `column` 节点声明了排序功能
- **THEN** 该列的排序能力随列定义交付给前端，由前端决定如何呈现

#### Scenario: 同一数据表由前端自主渲染
- **WHEN** 前端拿到同一个 `dataset` 描述
- **THEN** 前端可选择表格、卡片或其它形式呈现，描述与接口返回不因此改变

### Requirement: 组件可组合嵌套
系统 SHALL 支持任意组件被其它组件通过 `containers` 组合嵌套，包括被引用接口的组件；嵌套不得改变各节点自身的类型与数据契约。

#### Scenario: 接口组件被容器嵌套
- **WHEN** 一个由接口引用生成的组件被 `dataset` 或 `form` 节点嵌套
- **THEN** 该组件的类型、输入参数定义与渲染数据契约保持不变

#### Scenario: 深层嵌套
- **WHEN** 组件树嵌套深度超过三层
- **THEN** 每一层子组件都完整进入组件注册表并可通过接口获取

### Requirement: 组件描述接口返回内存注册表中的组件
系统 SHALL 提供组件描述接口，返回内存注册表中的组件类型定义与装配后的组件树，响应为 JSON。

#### Scenario: 正常返回
- **WHEN** 客户端请求组件描述接口且注册表非空
- **THEN** 返回装配完成的组件树与类型定义

#### Scenario: 注册表为空
- **WHEN** 注册表为空
- **THEN** 接口返回 HTTP 200 与空集合，不返回错误

#### Scenario: 响应为 JSON
- **WHEN** 客户端请求组件描述接口
- **THEN** 响应的媒体类型为 JSON

### Requirement: 前端在页面加载后通过接口获取并渲染组件
系统 SHALL 在前端页面加载后通过组件描述接口获取组件，按节点的 `type` 查找对应渲染实现并渲染，成功获取前展示骨架加载态。

#### Scenario: 页面加载即获取组件
- **WHEN** 前端页面完成加载
- **THEN** 前端发起组件描述接口请求并在拿到结果后渲染组件树

#### Scenario: 加载期间的骨架态
- **WHEN** 组件描述接口尚未返回
- **THEN** 页面展示骨架加载态而非空白页

#### Scenario: 由接口数据驱动菜单与路由
- **WHEN** 接口返回的组件树包含 `menu` 与带 `router` 的节点
- **THEN** 侧栏菜单与可访问路由由该组件树推导，不依赖前端静态配置

### Requirement: 未知组件类型降级为占位节点
系统 SHALL 在前端遇到注册表中不存在的组件类型时，将其渲染为带类型名的占位节点并记录告警，不阻断整页渲染。

#### Scenario: 存在未知类型
- **WHEN** 组件树中包含前端未实现的类型
- **THEN** 该节点显示为占位节点，页面其余部分正常渲染

#### Scenario: 未知类型包含子节点
- **WHEN** 未知类型节点带有 `containers` 子节点
- **THEN** 该子节点不被静默丢弃，页面不出现空白区域

### Requirement: 组件接口不可用时降级为本地声明
系统 SHALL 在组件描述接口不可用或响应不符合描述结构时，降级使用前端内置的本地组件声明，并保留全部导航与切换能力。

#### Scenario: 接口不可达
- **WHEN** 组件描述接口请求失败
- **THEN** 前端使用本地组件声明渲染，侧栏菜单可正常切换页面

#### Scenario: 响应结构不合法
- **WHEN** 接口返回内容不含 `type` 字段
- **THEN** 前端降级到本地声明并记录告警

#### Scenario: 接口恢复后重新获取
- **WHEN** 接口恢复可用且用户刷新页面
- **THEN** 前端重新从接口获取组件并渲染
