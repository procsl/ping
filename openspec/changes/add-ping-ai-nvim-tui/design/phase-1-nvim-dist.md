# 阶段 1 设计：Neovim 分发

对应 `tasks.md` 阶段 1（任务 1.1–1.5）。架构决策见 `../design.md` D11。

> 注：本文档待细化，当前只固定分发步骤、平台矩阵与失败处理。

## 分发步骤

```
识别平台 -> 解析版本与 URL -> 校验和 -> 落位 ~/.lwl/bin/
        -> 置可执行位 -> 后续启动直接复用（已存在则跳过）
```

- 分发是**幂等**的：目标文件已存在且可执行即跳过，不重新下载。
- 落位采用「临时文件 + 原子重命名」，避免中断留下半个二进制。
- 版本锁定在代码常量中，不跟随系统或最新版。

## 平台矩阵（第一版）

```
linux-x64   linux-arm64   darwin-x64   darwin-arm64
```

- Windows 分支不在本变更范围（见 `../design.md` Open Questions）。
- 平台标识由 os/arch 映射得出，映射表是唯一事实源，下载地址由「平台 + 版本」确定。

## 校验和

- 校验和随版本锁定写在代码中，不从网络获取。
- 校验失败即中止，不落位、不执行。

## 失败处理

| 触发条件 | 行为 |
|---|---|
| 无网络 / 代理拦截 | 明确错误：说明是网络原因，提示改用非交互形态 |
| 校验和不匹配 | 明确错误：说明是完整性问题，不落位 |
| 目录不可写 | 明确错误：给出路径与权限提示 |

**不假装降级成功**：交互形态没有替代渲染器，「获取失败」就是不可用（`../design.md` D11）。
